# Direct regional sync tickets

With direct regional routing, the application authenticates the user at one canonical bootstrap endpoint. That endpoint resolves DataFn namespace placement and returns a signed ticket plus approved HTTP and WebSocket URLs. Subsequent queries, mutations and sync traffic go directly to the owning cell. Clients never construct a URL from a region ID.

This feature is opt-in and provider neutral. Fixed `remote` clients, single-region servers, and [canonical gateway forwarding](./multi-region-gateway) continue to work. Direct tickets are a separate credential format from the single-request internal routing assertions; their keys and audiences should also be separate.

## Bootstrap at the canonical application

The application owns authentication and namespace authorization. `authenticate` must validate application credentials and derive an opaque subject and authorized namespace. Use a verified AuthFn consumer context or another authentication provider; do not take subject, namespace, region, epoch, or endpoint from request JSON or routing headers. AuthFn placement and DataFn namespace placement are separate authorities: resolve DataFn placement through the supplied directory.

```ts
import {
  createDatafnHmacRouteTickets,
  createDatafnRouteBootstrap,
} from '@datafn/server';

// Load at least 32 random bytes per key from your server-side secret manager.
const tickets = createDatafnHmacRouteTickets({
  activeKeyId: keyRing.activeKeyId,
  keys: keyRing.keys,
});

const bootstrap = createDatafnRouteBootstrap({
  directory: placementDirectory,
  signer: tickets,
  issuer: 'https://app.example.com',
  ttlMs: 60_000,
  authenticate: authenticateApplicationSession,
  authorize: identity => allowedDatafnScopes(identity),
  // This registry is owned by the application, never the caller.
  resolveEndpoint: placement => publicCells[placement.regionId],
});

// publicCells.eu, for example:
// { httpUrl: 'https://eu-data.example.com/datafn',
//   wsUrl: 'wss://eu-data.example.com/ws', audience: 'production:datafn:eu' }
// Mount bootstrap on POST https://app.example.com/api/datafn-route.
```

`authorize` returns permitted scopes: `query`, `search`, `mutation`, `transact`, `seed`, `clone`, `pull`, `push`, `reconcile`, `custom`, or `websocket`. Custom plugin routes default to the `custom` scope. Grant only operations the application authorizes. Resource authorization still runs at execution time.

Bootstrap rejects missing, moving, recovering, and tombstoned placements. It ignores client routing hints, returns `Cache-Control: no-store`, and includes only `version`, `httpUrl`, optional `wsUrl`, opaque `ticket`, `expiresAt`, and `renewAfter`. There is no diagnostic region ID or internal destination reference. If authentication supplies `expiresAt`, issuance is bounded by that deadline.

## Regional cell configuration

```ts
import {
  datafnMultiRegionPlugin,
  withDatafnRegionalCors,
} from '@datafn/server';

const regional = datafnMultiRegionPlugin({
  regionId: 'eu',
  directory: permissionDirectory,
  placement: {
    directory: placementDirectory,
    routeTickets: {
      verifier: tickets,
      issuer: 'https://app.example.com',
      audience: 'production:datafn:eu',
      allowedOrigins: ['https://app.example.com'],
      authenticate: authenticateApplicationSession,
      // Optional per-request/admission revocation and rate-limit adapters:
      isActive: claims => sessionRevocations.isActive(claims),
      allowRequest: claims => regionalLimiter.allow(claims.subject, claims.ticketId),
    },
  },
});

// Supply regional in createDatafnServer({ plugins: [regional], ... }).
const handleRegionalHttp = withDatafnRegionalCors(
  request => server.router.handle(request),
  { origins: ['https://app.example.com'] },
);
```

The server context/namespace provider must derive the same namespace from independently authenticated application context. The ticket is not application authentication. Regional validation checks signature, protected key ID/type/algorithm, issuer, audience, subject, namespace, session binding, region, epoch, scope, and times before plugin authorization or data execution. Placement is read linearly on every admission; there is no stale placement cache in this mode. Unknown/unavailable placement fails closed, even when a ticket is cryptographically valid.

Enabling `routeTickets` requires a ticket on external regional data routes. To accept canonical internal forwarding on the same cell, also configure the existing `assertionVerifier` and `replayStore`. Valid internal assertions retain their request/body/nonce checks. A request containing both credential types, or spoofed auxiliary internal routing headers, is rejected. Trusted in-process execution still performs placement validation without requiring a public ticket. The status endpoint remains a health endpoint and does not execute regional data operations.

## Client bootstrap and renewal

```ts
import {
  createDatafnClient,
  createDatafnHttpRouteProvider,
  MemoryStorageAdapter,
} from '@datafn/client';

const routeProvider = createDatafnHttpRouteProvider({
  bootstrapUrl: 'https://app.example.com/api/datafn-route',
  headers: () => ({ Authorization: `Bearer ${applicationAccessToken()}` }),
});

const client = createDatafnClient({
  schema,
  clientId: stableDeviceId,
  storage: new MemoryStorageAdapter(['note']),
  sync: {
    routeProvider,
    offlinability: true,
    ws: true,
    http: {
      headers: () => ({ Authorization: `Bearer ${applicationAccessToken()}` }),
    },
    // Optional application-specific WS authentication, independent of the route grant.
    // Your upgrade adapter must authenticate this protocol and negotiate only datafn-sync-v1.
    wsProtocols: () => applicationAuthSubprotocols(),
  },
});
await client.sync.start();
```

Alternatively implement `DatafnRouteProvider` with `bootstrap()` and `renew()`, both calling the canonical authenticated application authority. Neither method receives a cached regional destination. HTTP-only clients can omit storage and `ws`; regional WebSocket sync requires a storage adapter for cursors and checkpoints. A route provider cannot be combined with a custom remote adapter or native sync ownership. `DefaultHttpTransport` is also exported for transport-only consumers; pass its `routeProvider` option and call `dispose()` during teardown.

Each client owns one memory-only cache shared by HTTP and WebSocket sync. Concurrent refreshes are single-flight. Maximum-TTL validation allows up to five seconds of issuer/client clock skew; the descriptor expiry itself is never extended. Descriptors must provide a future `renewAfter`; already-due renewal timestamps are rejected. Renewal starts at 80% of lifetime by default; a failed renewal retries at bounded intervals while the old grant is valid. An independent deadline evicts the route even if renewal hangs. Reads also enforce expiry synchronously, superseding a pending renewal before starting a fresh bootstrap. Destroying the client discards the cache; switching authenticated context must recreate/destroy the client or use `switchContext` with the new provider. Nothing is stored in local storage, IndexedDB, native preferences, URLs, or sync checkpoints.

## WebSocket adapter contract

The browser offers `datafn-sync-v1`, `datafn-ticket.<opaque-ticket>`, and any configured application authentication protocols. A server adapter must:

1. Validate application authentication separately, including the origin policy.
2. Call and await `server.websocketHandler.addRoutedClient(socket, authContext, handshakeRequest)` before registering application listeners or accepting data-plane work. Supply the original request with its subprotocol header and a socket that supports `close`.
3. Negotiate only `datafn-sync-v1`; never reflect ticket/auth protocols in the selected protocol, logs, or errors.
4. Forward messages/pongs/disconnection to the existing `websocketHandler` methods.

Non-browser adapters can send the ticket in `x-datafn-route-ticket` instead of a subprotocol, but must not send both. Query-string tickets are never read. See the executable two-region fixture in `datafn/server/src/__tests__/regional-tickets-e2e.test.ts` for an adapter using Node HTTP and `ws`.

Sockets pin their region, epoch, and ticket deadline. Expiry closes the socket with `4511`; migration closes it with `4510`. The client goes back through canonical bootstrap before using a stale/expired route. HTTP renewal also replaces a socket's pinned grant via reconnect. Every socket open triggers a pull from the saved checkpoints to recover writes missed during the connection gap; if an older pull is running, recovery queues behind it and reads the updated checkpoints. Temporary admission throttling uses close code `4503` and retries with capped exponential backoff, even when the upgrade opened before admission rejected it. Transient transport closes and temporary throttling reuse a still-valid shared route, so HTTP and reconnects remain available during gateway outages until expiry. An HTTP-only descriptor skips WebSocket startup without a reconnect loop; HTTP sync remains available, and descriptor renewal can enable WebSocket support later. WebSocket authentication protocols are resolved only when a socket endpoint is available. Terminal authentication/revocation rejection uses `4403` (or adapter authentication code `4401`) and stops automatic reconnect; after reauthentication create a new client/context. `revokeRouteTicket(ticketId)` closes matching admitted sockets immediately in one process. Broadcast that command to every cell process holding the ticket for cluster-wide immediate revocation.

## Security profile and operations

Version 1 deliberately chooses a reusable short-lived bearer grant for HTTP and WS admission, with separate operation scopes, not per-request signatures or a one-shot connection nonce. TLS, independent application authentication, subject/namespace/session binding, and short expiry bound its reuse. Ticket theft together with application credentials permits replay until expiry/revocation. There is no proof-of-possession claim in this profile. Do not reuse DATA-1's nonce store: legitimate concurrent HTTP requests and socket reconnects reuse this grant. Existing mutation IDs provide application idempotency, not ticket replay prevention.

The bundled signer uses HS256 with a domain-separated signing input, protected `typ`, algorithm and `kid`, a unique ticket ID, and keys of at least 32 bytes. The signer/verifier interfaces permit deployment-owned cryptographic providers. All custom verifiers must authenticate their claims; the regional runtime still enforces claim shape, bindings, maximum lifetime, and timing. Keep signing keys server-side and grant verification access only to trusted cells; symmetric verifiers can also mint tickets.

| Concern | Policy |
| --- | --- |
| Lifetime | Default 60 seconds, maximum 5 minutes; all timestamps are Unix milliseconds. Bootstrap requires a configured TTL of at least 1 second. |
| Clock skew | Default 5 seconds for future issuance/not-before, configurable from 0 to 30 seconds. Expiry is strict and never extended. Monitor clock drift. |
| Revocation | Default bounded expiry. `isActive` checks ticket/session revocation at each HTTP request and WS admission; it is not background introspection of existing sockets. Use `revokeRouteTicket` on all processes for immediate socket revocation. |
| Key rotation | Construct a verifier with the new active key and bounded previous keys, then retire old keys after their grants expire. Removing a key rejects later admissions immediately; close existing sockets with the revocation/fencing API for emergency invalidation. |
| Audience | Unique per environment and regional endpoint; never share production and test audiences/keys. |
| Browser security | Exact origin allowlists; a regional Origin header is denied unless explicitly allowed. The HTTP client uses `credentials: omit`, a ticket header, and refuses redirects. No regional cookies or credentialed CORS. |
| CSRF | Regional calls require explicit route and application credentials. Canonical cookie-based bootstrap implementations must add their existing CSRF and Origin protections; the helper's POST-only policy is not a CSRF token check. |
| Preflight | The CORS wrapper answers valid OPTIONS without querying placement or invoking the data handler. It returns no placement details and never uses wildcard origins. |
| Exposure | Configure TLS, ingress/body/connection limits, rate limiting and DDoS controls on every public cell. `allowRequest` integrates a deployment-owned limiter before execution. |
| Privacy | Redact `x-datafn-route-ticket`, Authorization and Sec-WebSocket-Protocol in all proxies and logs. Grant callbacks emit only event type and error code. Hash subjects before adding application telemetry; never log tokens or raw namespaces. |

In-flight operations admitted before expiry may complete after expiry. There is no automatic cancellation or replay of an already executing mutation.

## Failures, retries, and migration

| Failure | Client behavior |
| --- | --- |
| `DATAFN_ROUTE_TICKET_EXPIRED` (401), placement mismatch/moving (409) | Invalidate the route and allow at most one canonical re-bootstrap/retry when `executionStarted: false` is explicitly present. |
| `DATAFN_ROUTE_RATE_LIMITED` (429), WS `4503` | Retryable throttling. WS retries use the configured capped backoff; no authorization-terminal close code is used. |
| Invalid/forged/scope mismatch, revoked ticket, denied identity | Fail without a transport replay or application-auth retry loop. |
| Gateway outage | Existing direct routes/sockets may continue only until strict expiry. New bootstrap fails with `DATAFN_ROUTE_BOOTSTRAP_UNAVAILABLE`; there is no region fallback. |
| Regional network failure | `DATAFN_REGIONAL_ENDPOINT_UNAVAILABLE`; never choose another cell and never automatically replay an ambiguous HTTP mutation. |
| Directory outage | Regional admission fails closed with `DATAFN_PLACEMENT_UNAVAILABLE`. A ticket alone is not proof of current ownership. |
| Invalid descriptor | `DATAFN_ROUTE_DESCRIPTOR_INVALID`; reject insecure URLs, URL credentials/query/fragment, unsupported versions and invalid deadlines. HTTPS/WSS is required except loopback development endpoints. |

Transport retries preserve the exact mutation body and mutation IDs. Offline push retains its existing deduplication-based retry contract; terminal server failures stop that attempt. Keep mutation IDs, records, change history, sequence counters, seed state, and checkpoints together during migration. The DATA-1 migration hooks must fence source sockets/writes, drain outboxes, copy and validate that state, then advance placement. Old tickets cannot route to the target; they fail the region/epoch check and require bootstrap. If the copy cannot preserve sync continuity, fail migration validation explicitly instead of activating an empty target or silently resetting a cursor.

For rollout, first mint/verify shadow grants, then enable `sync.routeProvider` for a limited cohort and compare regional acceptance/errors, bootstrap failures, renewal load, and ingress latency. Rollback client cohorts to the fixed canonical `remote` while retaining cell fencing; never roll back placement epochs. Existing direct grants can expire naturally or be revoked with key rotation plus socket closure. Production deployment and downstream product rollout remain application-owned.

## Validation

The repository's real HTTP/WS two-region conformance fixture verifies that the gateway receives bootstrap only, direct reads/writes and pull/push/reconcile succeed, a fenced migration preserves records/cursors/idempotency, a public client re-bootstraps on 4510, and gateway outage stops traffic at expiry. Ticket tests cover claim/algorithm/key tampering, key rotation, scope/subject/session/namespace/region mismatch, clock bounds, revocation, spoofed headers, CORS, and every built-in operation before authorization. Client tests cover concurrent refresh, hanging renewal, stale completions, invalid descriptors, bounded retries, and ambiguous mutation timeouts.
