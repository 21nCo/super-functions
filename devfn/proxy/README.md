# @devfn/proxy

Maintains one lock-protected, DevFn-owned Caddy route registry. Generated configurations contain concrete `.localhost` or explicitly registered local-domain routes and loopback targets only, are validated before reload, and include only a denying HTTP fallback for unknown hosts. Caddy binds to IPv4 loopback and adds IPv6 loopback when the host supports it; it never installs its internal CA in a trust store. Registered domains are bound to a repository and project in machine state. New or changed registered routes must resolve exclusively to loopback. Stopping one instance can retain another instance's established routes when its DNS is temporarily unavailable. If another Caddy owns the admin endpoint, DevFn refuses to replace its configuration.
