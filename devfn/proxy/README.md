# @devfn/proxy

Maintains one lock-protected, DevFn-owned Caddy route registry. Generated configurations contain concrete `.localhost` or explicitly registered local-domain routes and loopback targets only, are validated before reload, and deny unknown HTTP hosts. Selected TLS hosts redirect HTTP to HTTPS; unknown hosts receive 404. Caddy binds to IPv4 loopback and adds IPv6 loopback when the host supports it; it never installs its internal CA in a trust store. macOS uses unprivileged loopback ports 8080 and 8443, while Linux uses 80 and 443; published URLs include nonstandard ports. Registered domains are bound to a repository and project in machine state. New or changed registered routes must resolve exclusively to loopback and explicit certificates must cover every route hostname through a DNS SAN. Activated explicit certificates are kept as private immutable snapshots so sibling cleanup can reload after a source file disappears. DNS verification fails closed after five seconds so a stalled lookup cannot indefinitely hold the shared proxy lock. Stopping one instance can retain another instance's established routes when its DNS is temporarily unavailable. A pending activation with invalid DNS or certificate is rolled back to the last committed routes. If another Caddy owns the admin endpoint, DevFn refuses to replace its configuration.
