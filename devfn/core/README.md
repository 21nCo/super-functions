# @devfn/core

Builds dependency-ordered lifecycle plans, reserves ports before mutation, starts Compose and native resources, verifies readiness, registers shared proxy routes, emits machine-readable receipts, and rolls back only resources created by the failing invocation. The public `resolveEndpointTemplates({ config, plan, ownerId, ports, composeNetworks? })` API accepts an opaque owner chosen by its caller; see the [startup endpoint contract](../docs/configuration.md#startup-endpoint-and-template-resolution).

`resolveEndpointTemplates` runs before startup. Generated `DEVFN_*` keys are reserved, generated port aliases take precedence over same-key literals, and native loopback bind values are fixed; profile references resolve before node overrides, and explicit `{{env.NAME}}` references resolve in their selected consumer context. Native processes receive host-loopback `DEVFN_URL_*` values. Compose services receive sibling DNS URLs only when the caller supplies effective Compose network names for both services and they share a network in the same owner-specific project. The orchestrator obtains those names from `docker compose config` before creating state. A reference to an unreachable sibling URL or native loopback URL fails before state mutation. A service without such a reference omits unreachable sibling URLs.

Compose command readiness executes on the host. Its argv and `readinessEnvironment` therefore use host-loopback URLs, while `environment` retains the container URLs used for Compose interpolation. Startup, status, and retry use the same host-side values. HTTP readiness uses a directly reachable leased endpoint before selected proxy routes are installed, preserving the exact leased port even when an HTTPS route is probed over direct HTTP. Credential-bearing manifest values must use `envAllowlist` and `secretEnv`; they are excluded from endpoint resolutions and receipts.

The host command-readiness process inherits explicitly allowlisted values, including `secretEnv` credentials, at probe time. Other readiness types do not receive those credentials. The values stay out of resolved endpoint plans and receipt fields. A changed or missing inherited credential can make command readiness fail until the host environment is restored. Inherited host values do not enter startup fingerprints; declared key names do.

Template syntax and credential-bearing source values are checked before substitution. Credential names include `key`, `pass`, `pwd`, `auth`, `sig`, `token`, `secret`, `password`, and `credential` aliases, with separator or camel/acronym boundaries; compact names use documented qualifiers `api`, `app`, `auth`, `aws`, `client`, `db`, `database`, `google`, `oauth`, `pg`, `server`, `service`, `session`, `user`, `xamz`, and `xgoog`. This includes `PGPASSWORD` and qualified PostgreSQL password names. Credential-bearing headers are rejected after template expansion. Other ordinary compact words remain data. A referenced opaque owner remains literal data even when its bytes resemble template or credential syntax. Generated route hostnames and Compose project names include a digest of the exact owner bytes, so case-distinct owners have separate namespaces while receipts retain the original owner. Compose project comparison uses the same canonical name as Compose startup: its readable prefix is normalized, and a digest of the exact prefix distinguishes case and punctuation. Ready receipts fingerprint declared environment and command inputs, exact port requests, and secret key names without hashing inherited host values. Status reports a changed startup snapshot as degraded, and `up` safely cleans up the owned lifecycle before restarting it with the selected configuration. Older receipts without a startup digest retain v0.1 readiness behavior.

Native command, package script and command-health argv are also checked as vectors. `--user`, `--username`, `--proxy-user`, `-u` and `-U` accept ordinary names, but a colon-delimited credential pair is rejected in split, equals or attached forms. Percent-encoded URL and header credentials are checked before any startup mutation. The resolver inspects these forms without splitting or interpreting the argv used for execution.
Form and query options (`--data*`, `--form*`, `--url-query`, `-d`, `-F`) also reject credential-named `name=value` and `name@file` inputs in split, equals, attached and percent-encoded forms. Ordinary field names and literal shell metacharacters remain data.
Credential-named assignments inside attached long-option values, such as `--env=DB_PASSWORD=value` or `--build-arg=PGPASSWORD=value`, follow the same secret-channel rule. This includes encoded delimiters and name-only forwarding values; ordinary assignments such as `--env=NODE_ENV=development` remain argv data.
Structured argv checks inspect XML element and attribute names outside quoted attribute values. A `>` inside a quoted value does not end the tag, and credential-named attributes after it are rejected before startup; ordinary quoted text remains argv data.
