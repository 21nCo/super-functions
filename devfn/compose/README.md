# @devfn/compose

Requires Docker Compose 2.24.4 or newer. Starts only declared Compose services with `--no-deps` under a project name whose readable prefix is case folded and whose digest includes the exact prefix and opaque owner bytes; case-distinct prefixes remain separate even if their readable names normalize alike. It replaces source mappings with loopback or explicitly public DevFn host-port mappings while retaining conventional container ports, and never removes persistent volumes during ordinary cleanup. Secret-bearing services disable Docker log persistence.

Ready receipts fingerprint the selected effective Compose service, referenced volume/network/config/secret definitions, selected config-file contents, and noncredential environment values after Compose interpolation. Default and include-scoped env files participate when they affect that service; assignments with no effect and unrelated services do not. Ordered dotenv declarations preserve the value captured by an earlier assignment, while credential-derived config content is masked and an ordinary fallback remains part of the digest. Compose source references to inherited host variables such as `HOME` require an explicit `envAllowlist` entry, so ambient values do not silently enter a receipt. Credential-named and `secretEnv` values are excluded from the fingerprint; literal nonsecret fields retain their value even when the same bytes appear in a secret. Put credentials in `secretEnv`, not in Compose config files. Source graphs, alias expansion and local path interpolation are bounded before Compose reads them for endpoint planning. On Compose 2.24.4, a bounded source inventory supplies uninterpolated field provenance when its `--no-interpolate` option cannot open an interpolated `env_file` or bind-mount path.
