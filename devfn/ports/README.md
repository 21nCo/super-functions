# @devfn/ports

Machine-local, lock-protected port leases with worktree instance identity, exact/preferred/range/ephemeral allocation, stale reconciliation, listener discovery, Docker mapping discovery, and generated inventory reports. Reports enumerate the complete machine registry, including other projects and profiles, and are not a current-selection view.

Selected proxy routes claim Caddy's listener ports across TCP and UDP. One rule retires a claim, whether it was abandoned by an expired command, left by an interrupted lifecycle, or kept by a failed one: neither committed nor pending proxy state contains the instance's routes, and direct evidence proves that no listener remains. Successful socket inspection is not enough because a non-dumpable owner (a setcap Caddy on Linux) hides its sockets: every claimed port must refuse TCP connections on 127.0.0.1 and, when available, ::1, and must bind for UDP (Caddy's HTTP/3) on each of those addresses; an ordinary port must also bind for TCP on each. A privileged port whose UDP bind is denied, as for an unprivileged Linux user on 443, proves nothing, so its claim stays until a verified live Caddy owner's admin configuration excludes that port. A verified live owner may keep its admin listener after its last site is removed, but its live admin configuration must be readable and name no HTTP server listener on a claimed port; an absent, dead, or reused owner requires a free admin listener. Malformed route or owner state and unverified owner identity retain the claim for inspection. A healthy route or bound proxy listener keeps the ports protected while sibling worktrees start and stop.
Recovering an interrupted `planning` or `starting` invocation fails it but keeps its listener claim (`proxyClaimRetained`) unless that rule already holds. Releasing the last claim on a listener uses the same rule, so an invocation that ends with routes still in proxy state (for example after a failed replacement rollback) or while a Caddy it started may still listen (a failed start whose Caddy exit was not confirmed) keeps its claim the same way. Another running lifecycle of that instance claiming the same ports covers the claim; another instance's claim covers it only once this instance has no routes left. Garbage collection keeps such invocations until reconciliation retires their claims.
A port targeted by another instance's committed or pending proxy route stays unavailable to every other instance, even after its lease ended, until a route transition replaces or removes that route; the routed instance itself may lease it again to repair the route. Each invocation journals its owners in the registry, which outlives a deleted worktree: a Compose launch is recorded with its project, service and pre-existing containers before Compose runs, and the process (PID and start identity) or container IDs right after the receipt lists them; a process command runs only after its identity is recorded, so an interrupted process launch never starts it. Ready lease owners are copied there too, so reconcile and gc of leases never erase them. `devfn ports gc` removes the routes of an instance only when it can take that instance's lifecycle lock (no command of it runs) and every recorded owner of its invocations, including failed and interrupted ones, is verified dead: a process whose PID is gone or whose readable start identity differs, or a container Docker reports missing. A stopped invocation ended only after teardown verified every receipt and journal owner dead or stopped it by verified identity and resolved every launch; otherwise it stays `stopping` or `failed` and keeps its leases, routes and journal. A recently refreshed command, a launch with no recorded identity, a live owner, a live PID whose start identity cannot be read, an unreachable Docker endpoint, and a legacy running invocation with neither an owner journal nor a recorded owner all keep the routes; gc keeps a failed invocation while any of its recorded owners may run. Lease age and occupied target ports are never death evidence; an expired planned lease whose port is occupied becomes `externally-occupied`, not `stale`, and an active lease whose process identity cannot be read stays active. An `externally-occupied` lease keeps its invocation's listener claim only while one of that invocation's recorded owners may still run; once all are verified dead the occupant is foreign and the claim retires through the shared rule. Unreadable proxy route state fails reservation closed. Replacement preflight applies the same abandoned-claim recovery and routed-port rule before checking exact ports. Registry, domain and proxy mutations share a routing lock, so sibling claims cannot appear between replacement validation and route publication.
A stopping invocation, and a replacement holding its predecessor's leases, are protected only while their command refreshes them. Five minutes after the last refresh, reconciliation and claim recovery treat them like any other lease: owners verified as dead become stale, and live or ambiguous owners stay active.
