SearchFn is a Node-compatible HTTP server (`@searchfn/server`) plus an adapter. The deployment shape depends on which adapter you pick — the server itself runs anywhere Node, Bun, or Deno do.

## Where the index lives

| Adapter | Where state lives | Cold start friendly | Best fit |
| --- | --- | --- | --- |
| `MemoryAdapter` | Server process RAM | No (re-builds on every start) | Single-instance dev, tests |
| `IndexedDbAdapter` | Browser | n/a | Client side only |
| `PostgresAdapter` | Postgres | Yes | Most server deployments |
| `MeilisearchAdapter` | Meilisearch instance | Yes | Dedicated search service |
| `ElasticsearchAdapter` / `OpenSearchAdapter` | ES/OS cluster | Yes | Large scale |

Stateful adapters (everything except Memory) make the SearchFn server stateless — easy to scale horizontally, easy to deploy on any platform.
