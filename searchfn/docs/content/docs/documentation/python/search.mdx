---
title: Search
description: Rank Python inverted-index hits by matching row count.
---

`search_index(schema, db, query, model=None, limit=20, table_prefix="_searchfn_")` tokenizes the query and reads matching rows from the index table. The schema argument is retained for API compatibility; search reads the index rather than the source records. Pass `model` to restrict results to one indexed resource.

```python
from searchfn import search_index

hits = await search_index(schema, db, query="search world", model="articles")
# [{"id": "1", "model": "articles", "score": 2, "matches": ["search", "world"]}]
```

The function looks up each distinct query token once. It increments a result's score for **each matching index row**, so repeated or multi-field term rows can contribute more than one point. This is a simple term-row count, not BM25, field weighting, or length normalization. Results are sorted by score descending, then model and record ID ascending for stable ties. `matches` contains sorted distinct matched terms.

The function returns no hits for an empty or punctuation-only query. The HTTP handler instead rejects a blank query with `Missing query`; punctuation-only input still produces no hits. Both APIs convert `limit` using `int(...)`, so `1.9` becomes `1` and an integer string such as `"5"` is accepted. Booleans, non-convertible values, and non-positive converted values are rejected. The HTTP handler caps `limit` at 10,000 and returns an error envelope for invalid requests. SearchFn returns IDs and scores, not hydrated source records; read the records through your own adapter and authorization layer. See [indexing](/docs/documentation/python/indexing) and [HTTP mount](/docs/documentation/python/http-mount).
