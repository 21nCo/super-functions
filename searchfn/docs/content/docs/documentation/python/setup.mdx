## Install

```sh
pip install searchfn
```

The package requires Python 3.9 or newer and has no required runtime dependencies. Supply a schema containing `resources` or `models`, as a mapping or a list of named definitions. Each definition can hold fields as a mapping or a list; fields with `type: "string"` are indexed. Each record needs an `id`.

```python
from searchfn import create_searchfn_server

schema = {
    "resources": {
        "articles": {
            "fields": {"title": {"type": "string"}, "views": {"type": "number"}}
        }
    }
}
plugin = create_searchfn_server({"schema": schema, "db": db})
```

`db` is your async adapter. It must implement `find_many(table, where, limit=None)`, `create(table, value)`, and `delete(table, where)`. A DataFn adapter with those methods is one option. The Python kernel does not import DataFn.

## Index storage

Provision an index table in the same adapter before indexing. With the default `table_prefix`, the table name is `_searchfn_index`. Rows hold `term`, `model`, `recordId`, and `field`; an adapter may also assign an `id`. Configure a uniqueness rule for `(term, model, recordId, field)` if your database needs duplicate protection. SearchFn does not run migrations or create this table.

Pass `"table_prefix": "fts_"` to use `fts_index`. The prefix must be a non-empty string. The index route returns `{ "ok": true, "result": { "totalIndexed": ..., "totalTerms": ... } }`; the search route returns `{ "ok": true, "results": [...] }`. Mount and authorize them through your framework as shown in [HTTP mount](/docs/documentation/python/http-mount).
