---
title: Indexing
description: Scan configured string fields and replace index rows for each record.
---

`index_data(schema, db, model=None, table_prefix="_searchfn_")` reads `resources` or `models` from the schema and scans fields declared with `type: "string"`. It accepts field mappings and lists of named fields. With `model=None`, it scans all definitions; pass a name to scan one.

```python
from searchfn import index_data

result = await index_data(schema, db, model="articles")
# {"totalIndexed": number_of_records_with_terms, "totalTerms": number_of_rows_inserted}
```

For each record with an `id`, the indexer removes existing rows for that model and record ID, then writes a row for each token in each string field. The adapter must provide `find_many`, `delete`, and `create` for the index table. Provision that table first. Duplicate or unique-constraint errors on insertion are skipped; other errors propagate.

Tokenization lowercases the text, removes punctuation with `[^\w\s]`, splits on whitespace, and keeps non-empty tokens. Punctuation is removed rather than replaced with a separator, so `foo-bar` becomes `foobar`; Unicode word characters and one-character tokens can remain. Indexing is a full scan, not an incremental change feed. Schedule it for your data volume and re-run it after writes or use a host-specific update hook. See [setup](/docs/documentation/python/setup) and [search](/docs/documentation/python/search).
