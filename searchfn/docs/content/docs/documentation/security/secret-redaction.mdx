---
title: Secret Redaction
description: What SearchFn strips from log output — and what you still have to handle.
---

The server recursively redacts sensitive keys before passing context to your logger. You don't have to remember which fields are sensitive; the redactor does.

## Redacted keys (case-insensitive)

- `apiKey`
- `password`
- `secret`
- `token`
- `authorization`
- `connectionString`

When any of these appears as a key anywhere in the logged context — top-level or nested — its value is replaced with `[redacted]`.

```typescript
logger: {
  info: (msg, ctx) => console.log(msg, ctx),
}

// Internal log call:
logger.info("request.start", {
  operation: "index",
  payload: {
    resource: "articles",
    auth: { token: "secret-token" }, // logged as "[redacted]"
  },
});
```

## What's not redacted by default

- Generic credential fields you've named differently (`cred`, `apiSecret`, custom names).
- Query strings (could contain sensitive search terms).
- Document field values (could be PII).

For these you have to extend the redactor:

```typescript
import { createRedactor } from "@searchfn/server";

const customRedactor = createRedactor({
  keys: ["apiKey", "password", "secret", "token", "authorization", "connectionString",
    "creditCard", "ssn", "phoneNumber"], // your additions
});

const sf = await createSearchFnServer({
  adapter,
  logger: {
    info: (msg, ctx) => console.log(msg, customRedactor(ctx)),
    // ... etc
  },
});
```

(API note: `createRedactor` is exposed for advanced wiring; check the version you're on.)

## Don't log search queries

Search queries can reveal sensitive intent ("HIV treatment", "lawyer", "competitor name"). For privacy-conscious deployments:

```typescript
logger: {
  info: (msg, ctx) => {
    const sanitized = { ...ctx };
    if (sanitized.payload?.query) sanitized.payload.query = "[query]";
    log(msg, sanitized);
  },
}
```

## Don't log indexed document content

Indexed documents contain the data you're trying to search. Logging the full payload defeats most data-minimization goals. Default behavior: SearchFn does not log the document body — it logs counts (`indexed: N`) and resource names.

Custom code that calls the adapter directly is your problem. Don't `console.log(documents)`.

## Backend credentials

Adapter constructors take connection strings, API keys, and similar:

```typescript
new PostgresAdapter({ connectionString: "postgres://user:pass@host/db" });
new MeilisearchAdapter({ apiKey: "super-secret" });
```

These never reach the logger. The adapter stores them internally for outbound calls but doesn't surface them through any of the structured log paths.

Custom adapters: if you write one, follow the same rule — credentials should be read at construction and never exposed through diagnostics or error messages.

## Error responses

Server error responses never include stack traces or backend credentials. If your adapter throws an error containing sensitive data, the message is logged but **not** returned to the client.

What clients see:

```json
{ "ok": false, "error": { "code": "INTERNAL", "message": "internal error" } }
```

What you see in logs:

```
{"level":"error","msg":"request.error","errorCode":"INTERNAL","operation":"search","errorMessage":"ECONNREFUSED 10.0.0.5:5432","stack":"..."}
```

Audit log forwarders to make sure they don't include the verbose context elsewhere.

## OWASP A09 (security logging)

The redaction model is shaped by the OWASP A09 guidance — log enough to investigate, redact enough to not become a secondary breach surface. Test by injecting credentials into test requests and grepping the log stream.
