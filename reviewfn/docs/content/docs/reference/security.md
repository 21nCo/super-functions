---
title: Security model
description: Trust boundaries, Docker containment, credentials, and retention.
---

The trusted boundary contains the pinned installation, base-revision policy, context collector, coordinator and separate publisher. Repository files, retrieved text, test output and model output are untrusted.

The CLI clones the committed target into an owned independent checkout. Mutable tracked and untracked caller files are excluded. The source adapter independently rejects dirty review roots. Configuration is loaded from the immutable base revision in CI; a PR cannot select its own executable, commands or limits. Global execution configuration must be controlled by the runner administrator.

Tests require Docker; there is no host-execution fallback. The pinned Node 22 image runs with no network, no capabilities, no privilege escalation, a read-only root, an unprivileged UID, 1 CPU, 512 MiB memory, 128 PIDs, a 256 MiB workspace and 64 MiB temporary filesystem. Input archives are bounded at 256 MiB. Only the committed archive is mounted read-only; no home directory, credentials, source checkout, Docker socket or host output directory is available to tests. The entire container is removed on every terminal path, including successful parents with detached descendants. Commands share a batch deadline and have bounded output. Dependencies must be present in the trusted image or committed input; commands cannot install them over the network.

PR inference requires action-proxy authentication and the trusted `reviewfn-codex:0.154.0` image. Build its packaged Dockerfile before running. The review checkout is read-only; only a fresh owned result directory is writable on the host. CPU, memory, PID, temporary disk, runtime and output limits also apply to inference. The proxy endpoint provides inference access only; it must not embed a raw provider credential. The container has outbound networking for this proxy and receives no publication token or host home directory. Restrict its egress at the runner/network layer where repository confidentiality requires a single allowed destination.

Codex disables project-document loading and user config. Changes to `AGENTS.md`, `AGENTS.override.md`, `.codex/`, `.agents/`, or `.claude/` fail before inference. API-key and ChatGPT modes are available only for trusted local reviews without a PR identity. Access-token and workload-identity modes currently fail explicit compatibility preflight. There is no automatic authentication fallback.

The review CLI refuses a process environment containing `GITHUB_TOKEN`. Publication uses a separate trusted job and a retained report, without running repository code or inference. Use a per-repository/PR/profile concurrency group for cross-run serialization. Head checks occur after comment discovery and before comment/check writes. GitHub does not provide a transaction spanning head changes and comment creation; a race after a check is reported stale, and every comment names its reviewed SHA. Checks remain neutral.

Artifact filenames and metadata identities are validated. Reads and writes reject target and parent symlinks, apart from known root-owned macOS system aliases. Atomic private output writes occur outside the untrusted execution boundary. Retention validates matching metadata IDs before deletion. Tests retain redacted logs; transcripts require `retainTranscript: true`; events and all harness output are redacted using both detected secrets and the explicitly configured credential value. The CLI applies retention cleanup when saving a new run. Operators must schedule `new FileArtifactStore(artifactsDirectory, outputDirectory).deleteExpired()` for idle stores; the optional second directory includes CLI report.json/report.md copies in expiry cleanup. Shared content keeps the longest active expiration, including imports from run workspaces. Store mutations serialize through .retention.lock; after a crashed writer, the lock records PID, hostname, and acquisition time. Remove it only after confirming the owning process is dead on the recorded host; never reclaim an ambiguous or active owner automatically. Exports changed outside ReviewFn are preserved with a cleanup error rather than deleted. Failed copy writes retain expiry coverage for both old and proposed bytes; cleanup also removes content-addressed data orphaned before its metadata commit. The CLI saves the new review outputs but exits nonzero with REVIEWFN_RETENTION_CLEANUP_FAILED when cleanup reports errors.

Public forks never receive repository secrets. A proxy and isolated runner must be deliberately provisioned before enabling reviews. The publisher must download only the artifact from its trusted review job and verify PR/head/profile against event metadata. Never execute a PR-owned workflow, package or image with publication credentials.

Linked Linear document URLs must share the server-returned issue URL workspace, and returned canonical document URLs are rechecked before their content enters review context. Issue-attached document records inherit their verified issue association. Missing optional Markdown globs are accepted as empty selections; use an exact file path when absence must make context incomplete.

Host snapshot checkout, source capture, and test archive preparation use credential-free Git environments with system/global configuration disabled; checkout also disables templates, hooks, and global attributes. Reproduced findings require a completed reviewed-head test receipt and retained logs whose digests verify. Requirement text alone cannot substantiate a defect finding.

Deleted changed paths may use verified merge-base code anchors only when the source adapter proves the path is absent from the head. Existing paths still require head-commit anchors.


Native tool lookup on Windows resolves `.exe` binaries and rejects repository-owned paths; shell-dependent `.cmd`/`.bat` wrappers are not supported. POSIX world-write and execute-bit checks apply only on POSIX. Windows operators must provision PATH directories with trusted ACLs: Node's `stat.mode` does not validate Windows ACL ownership. Native Windows executable-name handling has regression-test coverage by simulating `process.platform` on POSIX. The full consumer and Docker gates remain verified on POSIX, not Windows end to end.

Normalized Codex telemetry is capped at 10,000 retained events including a truncation warning. If the limit is reached, successful inference still records incomplete telemetry scope, while timeout and cancellation outcomes retain their terminal state.
