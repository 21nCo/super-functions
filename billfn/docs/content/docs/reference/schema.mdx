title: Schema

---

`getSchema()` in `@billfn/core` currently returns version `2` with twelve table definitions.

## Tables

| Table | Purpose |
| --- | --- |
| `billingAccounts` | Stable internal owners for user or organization billing state |
| `subscriptions` | Normalized provider subscription snapshots |
| `checkoutSessions` | Checkout lifecycle and provider reference ids |
| `entitlementSnapshots` | Current feature and limit projection for an account |
| `usageMeters` | Current usage per billing account and resource |
| `usageLedger` | Append-only usage deltas |
| `webhookReceipts` | Dedupe and audit trail for provider webhook deliveries |
| `billingEvents` | Internal normalized billing event stream |
| `refunds` | Normalized refund and revoke operations |
| `subscriptionChangeRequests` | Subscription change intent and fallback tracking |
| `reconciliationJobs` | Operational replay and sync jobs |
| `reconciliationCursors` | Provider backfill cursors |

## Important Indexes

Phase 1 relies on a few critical indexes:

- `subscriptions.provider + providerSubscriptionId` as a unique provider reference
- `subscriptions.provider + providerChargeId`
- `checkoutSessions.provider + providerCheckoutId`
- `checkoutSessions.provider + providerSubscriptionId`
- `checkoutSessions.provider + providerChargeId`
- `entitlementSnapshots.billingAccountId` as a unique current snapshot
- `usageMeters.billingAccountId + resource` as a unique usage meter
- `webhookReceipts.provider + providerEventId` as a unique dedupe key

## Example

```ts
import { getSchema } from "@billfn/core";

const schema = getSchema();
console.log(schema.version);
console.log(schema.schemas.map((table) => table.modelName));
```

The Python SDK mirrors schema version `2`, including the four lifecycle and reconciliation tables. Both helpers expose the same twelve logical model names and mark record identifiers as unique.
