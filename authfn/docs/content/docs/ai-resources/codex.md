# Codex / Droid (and any AGENTS.md-aware tool)

The [AGENTS.md](https://agents.md) convention is supported by Factory's Codex and Droid CLIs as well as several other agentic tools. Drop an `AGENTS.md` at the root of your repo with a section dedicated to authfn.

## Repo-root AGENTS.md

```markdown
# Project Agents

## authfn

When working with `@authfn/*`:

- Mount path is `/auth`.
- Plugins enabled: password, email-otp, social-oauth (Google), 2FA, api-keys.
- Database is Postgres via Drizzle.
- The schema is generated by `npx superfunctions auth schema` and lives in `apps/api/src/db/generated/authfn-schema.ts`.

Authoritative docs: https://authfn.superfunctions.dev
For a full-text RAG file: https://authfn.superfunctions.dev/llms-full.txt

If you have access to MCP tools (`authfn.docs.search`, `authfn.openapi.operation`, `authfn.skills.invoke`), prefer those.
```

## Factory Droid MCP setup

```bash
droid mcp add authfn npx -- -y @authfn/mcp
```

Then in any droid session:

```text
@authfn how do I add a Microsoft Entra OAuth provider?
```

The droid will route the question through the authfn MCP tools.

## Codex CLI setup

```bash
codex mcp add authfn npx -- -y @authfn/mcp
```

(Same pattern as Droid.)

## Skill packs in CI

If you run agents in CI to generate stub PRs, point them at specific skills:

```bash
droid run --skill authfn:add-2fa "Add a /settings/security page that lets users enroll in 2FA."
```

The MCP server returns the `add-2fa` playbook + relevant docs as context, so the generated PR follows the supported pattern.
